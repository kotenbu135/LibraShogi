- 対象: `libra-v0.3.pt`（PyTorch のチェックポイント）と `libra-v0.3.onnx`（fp32、opset 17）
- 版: **v0.3**（本体 run `ls` の **step 812,226**、2026-10-04 06:55:46（日本時間）に到達。自己対局の総局数 **10,000,000 局**）

## 1. 何のモデルか

**天秤将棋**（https://tenbinshogi.com/rules/ 、本リポジトリの規定は [rules.md](rules.md)）を指す AI「Libra」の方策・価値ネット。
1 手目から 40 手目までの布石（駒を打って陣を作る段階）と、41 手目以降の本将棋の両方を 1 つのネットで扱う。
USI を拡張したエンジン（`libra` / `libra.exe`、[protocol.md](protocol.md)）から ONNX Runtime で読み、MCGS（Gumbel AlphaZero 系の探索）の評価に使う。

**v0.2 の続きである。** v0.2（step 317,975、360 万局）と同じ run `ls` を止めずに学習し続け、総局数 1,000 万局の節目で保存した重みをそのまま v0.3 にした
（学習率を下げる「仕上げ」はしていない。[decisions.md](decisions.md) 2026-10-03）。

## 2. ネットの形

**v0.1・v0.2 から変えていない**（`[net]` は run を替えない限り固定）。

| 項目 | 値 |
|---|---|
| 種類 | Transformer エンコーダ（81 マスをトークンにする） |
| `d_model` / 層 / ヘッド / `d_ff` | 320 / 8 / 8 / 1280（dropout 0.0） |
| パラメータ数 | **10,233,090**（約 10.2M） |
| 入力 `sq` | `float32[batch, 81, 32]`（マスごとの特徴） |
| 入力 `glob` | `float32[batch, 32]`（持ち駒・手数・段階などの大域特徴） |
| 出力 `policy` | `float32[batch, 2268]`（指し手・打ち手のロジット） |
| 出力 `wdl` | `float32[batch, 3]`（手番側の 勝ち / 引き分け / 負け のロジット） |
| 出力 `v41` | `float32[batch, 3]`（41 手目局面の見立て。布石の価値の補助ヘッド） |
| ONNX | opset 17（既定ドメイン）、バッチ可変 |
| ONNX のメタデータ | `libra_step=812226`、`libra_net={"d_model":320,...}`、`libra_source=libra-v0.3.pt`、`license=Apache-2.0` |

ONNX と PyTorch の出力の差は最大 7.8e-05（書き出し時の照合）。
特徴量の作り方は `libra-sim`（`Position.features`）と `libra-net/libra_net/` が正。

**重みは「重みの平均」（EMA）である。** 2026-09-28 から、学習中の重みを一定の間隔で指数移動平均した重みを自己対局・計測・書き出しに使っている（§3）。
`.pt` の `model` が平均の重み（推論と ONNX はこちら）、`model_raw` が学習中の重みで、学習を続けるときは `model_raw` と `opt` を使う。
ほかに `step`・`ema_updates`・`rng`・`config`・`state` が入っている。

## 3. どう学習したか

**自己対局だけ**で学習した（AlphaZero 型）。教師データ・定跡・人の棋譜は使っていない。

| 項目 | 値 |
|---|---|
| 学習の系列 | 2026-09-18 に**ゼロから**始めた run `ls`（v0.2 と同じ系列。種の重み無し）。ルールは二飛香（[rules.md](rules.md) §3.2） |
| step 812,226 時点 | 自己対局の総局数 **10,000,000 局**、経過 約 279 時間（v0.2 からは 640 万局） |
| 自己対局の探索 | 全読み 96 回（確率 0.25）／軽い読み 24 回、Gumbel の候補 16 / 8、`policy_topk` 32、`c_visit` 50.0、`c_scale` 1.0、fp16、同時 512 局・12 スレッド（v0.2 と同じ） |
| 学習 | batch 1024、lr 2e-4（warmup 1,000。下げていない）、weight decay 1e-4、`replay_ratio` 1.0、**窓 = min(総局数の 50%, 200 万局)**（この時点で 200 万局）、256 局ごとに学習、`grad_clip` 1.0、`mirror_prob` 0.5 |
| 損失の重み | policy 1.0、value 1.0、v41 0.5 |
| 布石の価値目標 | 結果 `z` そのもの（`lambda_z` = 1.0。v0.2 と同じ） |
| **重みの平均（v0.2 から追加）** | `[train] ema_scale` 8（平均に足す割合 1/8）、`ema_period_samples` 500,000（約 488 step ごとに更新）。2026-09-28 から（総局数 600 万〜640 万局の間）。比べの試験で、そのままの重みより +51.1 Elo（[decisions.md](decisions.md) 2026-09-28） |
| **投了（v0.2 から追加）** | 2026-09-21 から有効。根の探索値（手番側から見た −1〜+1）が −0.9 以下になったら投了（勝率にしておよそ 5% 以下。40 手目までは投了しない）。10 局に 1 局は投了せずに最後まで指し、誤投了を測り続ける（[decisions.md](decisions.md) 2026-09-21・09-22） |
| **後手玉の四段目（v0.2 から変更）** | 自己対局で 2 手目の後手玉を四段目に置く割合を 25%（一様乱数のまま）から **5%** に下げた（2026-09-24〜。四段目の後手玉は 41 手目の裁定でほぼ負けるため。計測の対局は一様のまま） |
| 搾取者・リーグ | **本体の学習には使っていない**（`[selfplay] openings = ""`、`[league] enabled = false`）。搾取者 `lx` は別の run として 2026-09-23〜10-02 に回したが、その局は本体の学習に入れていない（§6-3） |
| 玉の置き方 | 1 手目の先手玉は 36 マスから一様乱数、2 手目の後手玉も自陣 36 マスから乱数（ただし四段目は上のとおり 5%） |
| 終局規定 | [rules.md](rules.md)（千日手 4 回で引き分け、連続王手は王手側負け、入玉宣言 27 点法、本将棋 320 手、41 手目を 1 手目として数える） |

**クリーンルーム**: 既存の将棋 AI（やねうら王、Apery、dlshogi、Lc0、水匠、Stockfish、fuseki-shogi-ai、fuseki-shogi-web など）のコード・評価関数・重み・棋譜・評価値・読み筋を、内部にも学習信号にも使っていない（[CONTRIBUTING.md](../CONTRIBUTING.md)）。GPL のコードは一行も含まない。

## 6. 既知の限界

1. **補助ヘッド `V̂41` は結果より低めに出る**（`v41_minus_z` −0.052。v0.2 は −0.046）。布石の価値目標は結果 `z` そのもので（目標と結果の差 0.000）学習には効かないが、`v41` の出力をそのまま読むときは低めに出ることに注意する。
2. **本将棋（41 手目以降）の探索値が結果より低い。** 自己対局の本将棋の局面で、探索値が結果より 0.072 低く出る（`rootq_minus_z_normal` −0.0723。v0.2 は −0.054）。外部の相手との対局が無い（§5.7）ので、読み抜けかどうかは直接は測れていない。
3. **搾取者に対する穴は未計測。** 搾取者 `lx`（本体の弱点ばかり探す小さいネット）を 2026-09-23〜10-02 に回したが、本体の読みを 1 回から段階的に増やす課程の途中（本体の読み 12 回で勝率 49%）で止めた。**本番の本体（読み 96 回）に対してどれだけ勝てるかは測っていない。**
4. **強さを揃えた条件で、外部の相手と測っていない。** §5.1〜5.6 はすべて自分の過去の版が相手で、絶対的な強さは分からない。外部エンジンに対する強さは 1.0 で測る。
5. **920 万局の重みより強いとは言い切れない**（§5.3）。とくに布石だけを替えると 2 回続けて負けている（§5.6）。本将棋の伸びで全体はわずかに上回っている見込みだが、区間が 0 をまたぐ。
6. **玉配置表（`scale.json`）を配らない。** 1〜2 手目の両玉は `libra.exe` が読んで置く（先手玉は六段目を除いて乱数、後手玉は四段目を除く候補を読んで先手の勝率が五分にいちばん近いマス。[protocol.md](protocol.md) §2）。読む回数（`Sims_Fuseki` か持ち時間）が少ないと、後手玉の置き方の精度が落ちる。
7. **ルールの版が固定。** 二飛香を含む今の [rules.md](rules.md) だけを扱う。`Fuseki_Rules` を名乗らないので、二飛香より前の棋譜を読ませると `info string bad position` と `bestmove resign` になる。
8. **入力は 天秤将棋 / 布石将棋 専用。** 本将棋（通常の将棋）の初期局面からは指せない。

## 7. 使い方

```
# Linux（ONNX Runtime、CUDA / CPU）
bin/libra-usi                     # DNN_Model に libra-v0.3.onnx を指す

# Windows（配布物の zip）
libra.exe                         # 隣の libra.onnx を読む。既定は DirectML
```

USI の申告と `info` の形式は [protocol.md](protocol.md) §3。天秤将棋の GUI（tenbin-shogi-desktop 0.10.0 以降）は
1 回登録すれば 1 手目から終局まで指させられる（同 §1・§2）。
**v0.3 から玉配置表を使わない。** `Scale_Table` の既定は空で、両玉は読んで置く。v0.2 の `scale.json` を隣に残していても読まない
（使いたいときだけ `setoption name Scale_Table value <場所>` を送る。ただし v0.2 のネットで作った表なので v0.3 とは合わない）。
**v0.2 の `libra.exe` を登録済みの人は、入れ替えたあとに GUI でエンジンを登録し直す**（名乗りが `LibraShogi 0.2.0` から `0.3.0` に変わり、一覧の表示名が変わるため）。

## 9. 配布物の作り方

```bash
# 1. Windows 版をクロスビルド（libra-engine/README.md）
export PATH="$PWD/.venv/bin:$PATH"   # cmake と ninja は pip 版（sudo が使えないため）
cmake -S . -B build-win -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64-posix.cmake \
  -DLIBRA_BUILD_PYTHON=OFF -DLIBRA_BUILD_TESTS=OFF -DLIBRA_ORT_DIR=$PWD/third_party/onnxruntime/onnxruntime-win-x64-directml-1.24.4
cmake --build build-win
# 2. Release に載せるものを作る（zip・SHA256SUMS）
tools/package_release.sh v0.3 ~/libra-run/releases/v0.3 '2026-10-04 06:55:46'   # 末尾は自己対局の標本の中心の時刻
```

zip の中身は `libra.exe`、DirectML 版 ONNX Runtime 1.24.4 と DirectML の DLL、`libra.onnx`（＝`libra-v0.3.onnx`）、
`README.txt`、`MODEL-CARD.md`、`LICENSES/`（Apache-2.0・CC BY 4.0・CC0 1.0・NOTICE・依存物の全文と ThirdPartyNotices）。
**v0.3 から `scale.json` は入っていない。** zip と標本の gzip は日時を固定して詰めるので、同じ入力からは同じ SHA-256 になる。

エンジンが名乗る版は `id name LibraShogi 0.3.0`（`libra-engine/src/engine.cpp` の `VERSION`。エンジンの版で、重みの版とは別）。
