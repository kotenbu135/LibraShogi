# 決定の記録

1 行 1 決定。日付、内容、理由。ユーザー（ルール設計者）の判断が要る事項は「要確認」と書き、確定したら書き換える。

- 2026-09-11 終局規定は大会規定（WCSC 大会ルール）に統一。ルール設計者の決定（docs/libra-local.md §0.1）。
- 2026-09-11 公開は v0.1 で行う。それまで非公開。ルール設計者の決定。
- 2026-09-11 設計書・実行計画を docs/ に置く（CLAUDE.md の参照先に合わせる）。
- 2026-09-11 LICENSE は apache.org の Apache-2.0 原文をそのまま置いた（リモートが空で作成時の LICENSE が無かったため）。
- 2026-09-11 非公開の間の CI は ubuntu-latest のみ。cmake/ninja/pybind11 は pip で入れる（ランナーにも WSL にも sudo 無しで入るため）。
- 2026-09-11 Libra は GUI の `Fuseki_Mode`（tenbin|fuseki）を申告して受ける。GUI は `Fuseki_` で始まる申告があるエンジンだけを「布石にも対応」と自動判定するため（docs/protocol.md）。
- 2026-09-11 Libra の `info` は常に `winrate` を出す。`score cp` は仕様 v0 の S=435・offset +34 で作る（GUI は winrate を優先するので目盛りの問題は出ない）。
- 2026-09-11 手数上限は WCSC36 大会ルール第 27 条 3 項の 320 手に揃え、41 手目を本将棋の 1 手目として数える（通算 360 手目で上限）。ルール設計者の決定。libra-sim・libra-search・libra-league の既定値と L-S の config.toml を 320 に変更（L-S は stop → run で継続。それまでの 256 手引き分けの棋譜はそのまま窓に残す）。
- 2026-09-11 40 手完了時の SFEN の手数は通算の 41（desktop の wasm `fw_to_sfen` と一致させる）。libra-sim の `ply` は常に通算、`normal_ply` は本将棋で指した手数。
- 2026-09-11 勝率→cp の丸めは JS の `Math.round`（.5 を +∞ 側へ）に合わせる（GUI の `winrateToCp` と 1 の位まで一致させるため）。
- 2026-09-11 布石将棋モードで最後の 1 枚が玉のときの 40 手目は「打った後に玉が当たらない手だけ合法」と読む（docs/rules.md §3.3）。天秤将棋では生じない。
- 2026-09-11 本将棋の合法手生成は「疑似合法手＋移動後の占有で自玉の安全を判定」方式。打ち歩詰めは相手の合法手の有無で判定。速度は後回し（平手 perft で 17 Mnps）。
- 2026-09-11 ビルドは pip の cmake/ninja/pybind11 と `.venv`（sudo 不要）。CI も同じ。
- 2026-09-11 Libra-L（L-S）のネットは d=320・8 層・8 ヘッド・FFN 1280 の Transformer（約 10M）。81 マス＋グローバルの 82 トークン、2D 相対位置バイアス。
- 2026-09-11 探索は全読み 96 sim（Gumbel m=16）25%、速読み 24 sim（m=8）75%、平均約 42 sim。方策ターゲットは全読みだけ、価値は全局面。布石の価値ターゲットは 0.5·z ＋ 0.5·V̂41。
- 2026-09-11 木は 1 手ごとに作り直す（サブツリー再利用なし。メモリを 512 局 × 数百ノードに抑えるため）。布石中は探索内で Zobrist 合流。
- 2026-09-11 自己対局と学習は 1 プロセスで時分割。新規 256 局ごとに「局面数 × replay_ratio 4 / batch 1024」ステップ。推論は fp16、学習は bf16 autocast。
- 2026-09-11 玉配置ペアは当面一様サンプル（36×36）。libra-scale の重点サンプルと搾取者は後で足す。
- 2026-09-11 WSL のディストリ名は `Ubuntu-24.04`（計画書の `Ubuntu` ではない）。Task Scheduler の登録はこれに合わせた。
- 2026-09-11 df-pn は Nagai の手法を参考にゼロから実装（置換表は直接写像、節点上限で打ち切り）。本将棋の節点鍵には千日手の回数を混ぜて GHI を減らすが完全ではない。証明は「根の手の選択」と「探索の終端値」にだけ使い、裁定は常に libra-sim で行う。
- 2026-09-11 布石終盤（36 手目以降）の証明探索は攻め方の手を「相手玉に当たる飛角香桂の打ち手＋駒種ごとのパス」に絞る（証明は健全、反証は不完全）。受け方は全合法手。証明だけを終端値に使う。
- 2026-09-11 本将棋の詰み探索は各手の根で 200 節点だけ（葉では行わない）。証明できればその手を指し、方策ターゲットはその手の one-hot。
- 2026-09-11 desktop への終局判定（宣言法・千日手・手数上限）追加と、GUI で Libra の玉配置表を使う改修は、Libra 側の準備ができた時点で tenbin-shogi-desktop に Issue を起票する。ルール設計者の決定。それまで GUI 対局は `Declare_Win=false`。
- 2026-09-11 mingw-w64 をルール設計者が apt で導入（`x86_64-w64-mingw32-g++` 13-win32）。libra.exe のクロスビルドはこれを使う。
- 2026-09-11 自動ログオン（netplwiz）と GPU 電力上限の変更は行わない。ルール設計者の決定。再起動後の再開は手動ログオン後に Task Scheduler が行う。
- 2026-09-11 libra / libra.exe は ONNX Runtime 1.30.0（MIT）の C API を実行時に dlopen / LoadLibrary で読む（リンクしない）。EP は auto で CUDA → DirectML → CPU。公式バイナリは `tools/fetch_onnxruntime.sh` で取得し SHA-256 を固定、リポジトリには入れない（third_party/ は gitignore）。
- 2026-09-11 Windows 版は WSL の mingw-w64 posix 版で静的リンクし、`onnxruntime.dll`（CPU 版）だけ同梱。CUDA・cuDNN の DLL は同梱しない。DirectML 版 DLL の同梱は Windows で GPU が要ると分かってから判断する。WSL 経由（`bin/libra-usi`）なら CUDA EP で動く。
- 2026-09-11 ONNX は fp32・opset 17・バッチ可変。メタデータに step とネット設定を入れる。fp16 化と複数葉の同時評価（DNN_Batch_Size）は速度が要るときに入れる（現状は 1 葉ずつ評価）。
- 2026-09-11 エンジンの `stop` は go を読んだ後に届いたものだけ効く（読み取りスレッドが go でフラグを消す）。探索結果が無いまま止められたら投了ではなく合法手の先頭を指す。
