- 2026-09-13 `libra run` を監視役にし、ランナー本体を子プロセス（`run --no-supervise`）で回して、異常終了したら 60 秒後に起動し直す。起動し直さないのは終了コード 0（STOP）、3（二重起動。従来の 1 は例外終了と区別できないので変えた）、SIGINT/SIGTERM/SIGHUP（利用者や OS が止めた。監視役に届いたら子へ転送して抜ける）、待機中に STOP フラグが置かれたとき。15 分（チェックポイント間隔より長く）未満で落ちるのが 5 回続いたら諦めて子の終了コードで抜ける（長く動いた後の落ち方は数え直すので、数時間に 1 回の故障で積み上がらない）。子の標準出力・標準エラーは `<run>/stdout.log` に追記する（従来は vbs 経由で捨てられ、CUDA のエラー文がどこにも残らなかった）。run.lock の pid は /proc/<pid>/cmdline に libra_league を含むときだけ生きているとみなす（pid の使い回しを二重起動と取り違えて監視役が抜けるのを防ぐ）。理由: 9/13 07:21 に lx が CUDA の illegal memory access で abort し、タスク スケジューラの RestartOnFailure は起動後の異常終了では再起動せず 4.7 h 止まった。abort はプロセス内で復帰できないので、再起動は親プロセスが行う（ユーザー了承済み）。稼働中の ls・lx には次に起動し直したときから効く。
- 2026-09-13 ランナーが abort で落ちたときの自動計測ジョブの後始末: ジョブの起動時に pid と引数を `<run>/auto_job.json` と state の running に書き、起動し直したランナーは load() の直後に `AutoJobs.recover()` で、生きていればそのプロセス グループ（start_new_session なので pgid = pid。match の相手エンジンも含む）を SIGTERM → 10 秒後 SIGKILL で止め、ジョブを待ち行列の先頭に積み直す。pid はコマンド行に出力先のパスを含むときだけ本人とみなす（使い回された pid を止めない）。最後の保存より後に起動したジョブは state では待ち行列に残っているので二重に積まない。途中まで書いた出力は `.interrupted` に改名する（match の棋譜 JSONL は追記で開くので、同じ `--out` で走り直すと途中の局が混ざる。stop() の積み直しにも同じ問題があったので揃えた）。結果の途中回収はしない（anchor の記録は rc=0 の終了を見て書くので、走り直すほうが素直）。理由: abort は stop() を通らず、孤児が GPU を使い続けたまま監視役が 60 秒後に起動し直すと次の計測と二重に走り、中断したジョブは消えていた。
