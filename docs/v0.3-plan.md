やり直しの系列（2026-09-17〜）では lx をまだ足していない。docs/runbook.md 冒頭の「本体が最強比で伸び始めてから足す」という前提は**満たしている**（2026-09-21 の最強比は step 317,975 が +37.0 Elo、区間 [21.7, 52.4]、2,000 局）。

**入れる前に要るもの**（2026-09-21 に 3 つとも中身を確かめ直した）

- **`config/lx.toml` を作る**（`config/` にあるのは `ls.toml` だけ）。docs/runbook.md §設定の管理は「中身を推測せずそのランの `config.toml` を写す」だが、**写す元が無い**: 2026-09-21 に `~/libra-run/lx/config.toml` を読んだところ、9/17 に `lx` → `lx-v1` へ改名したあとの**空のディレクトリで `libra run` が走って書かれた既定値そのまま**の中身だった（`run_id = "ls"`、`main_ckpt`・`main_source`・`openings_out`・`pool_out` がすべて空、`[train]` はやり直しの原因になった窓 10 万局・`replay_ratio` 4、`[auto]`・`[progress]` は無効。`libra_league/runner.py` の「`config.toml` が無ければ既定値を書く」の出力）。**この中身を写してはいけない。** 代わりに `config/ls.toml`（値の出所が docs/ls2-settings.md にある今の設定）を土台に、lx 専用の節だけ docs（decisions.md 2026-09-13・09-14・09-17、runbook.md §搾取者）に記録された値で埋める。
- **凍結相手 `lx/main.pt` の作り直しは手作業ではない**（2026-09-21 に実装を読んで確かめた）。`[exploiter] main_source` に本体の `checkpoints/latest.pt` を指し、`refresh_steps` / `refresh_hours` を入れておけば**起動直後に作り直す**（runbook.md §搾取者「初回は起動直後に行う」）。要るのは設定だけ。

## 2. 自己対局の後手玉四段目を 25% から減らす（候補、未決）

自己対局は 1〜2 手目の玉を**方策ではなく 36×36 のマスから一様乱数で置いている**（`libra-search/src/selfplay.cpp` の `start_game`）。後手玉の 36 マスのうち 9 マスが四段目なので**四段目はきっかり 25% 出る**。四段目は 3 手目の桂打ちが docs/rules.md §3.4 の遮断不能になり、40 手完了時の裁定で先手の勝ちが確定するので、41 手目に届かない。

- **もったいなさ**: 学習に入る局面の約 11% が「もう決まっている局面」（2026-09-21 の measurements.md）。0% にすれば同じ GPU で実質の局数が 1 割ほど増える**見込み**。
- **この見込みは過大**: 41 手目以降は根の詰み探索（`mate_nodes_root`・`proof_nodes`）のぶん 1 手が高く、短い布石だけの局を長い局に置き換えると 局/日 はその比ほど戻らない。**未検証**。
- **丸ごと除かない**（§5）。**25% → 5% 程度に減らす**のが案。
- **要る改造**: 今は真偽値（`search.prune_gote_rank4`。2026-09-11 に搾取者用として作ったもの）なので、確率にする小改造が要る。
- **入れたあとに確かめること**: 後手玉四段目の 2 手目の局面でエンジンが返す `winrate` が 0.5 以上のままか（`position fuseki moves K*<先手> K*<後手の四段目>` ＋ `go` を直接送る）。§5 の理由がここに掛かる。

## 3. 投了を有効にする（2026-09-21 に入れた）

`config/ls.toml` の `[search] resign_threshold` を 0.0 → **0.9** にした（**ユーザーの決定「投了を先」**。decisions.md 同日）。`resign_runs = 1`・`resign_disable_prob = 0.1`・`resign_min_ply = 40` は既定と同じだが、決めた値なので明示して書いた。**反映はユーザーのコンソールの停止 → 起動**（既にあるキーなので `git pull` は要らない）。

**確かめる計測**（400 万局・440 万局の節目）: (a) 最強比 2,000 局の Elo が下がっていないこと、(b) `gen` の held-out と窓の中の差が広がっていないこと、(c) 局/日 が 58 万局/日 から上がること。**下がったら 0.0 に戻す。**

**窓の心配はしなくてよい**（2026-09-21 に数え直した）: リプレイの窓は局数で数えるので 1 局が短くなると窓の中の局面が 2 割減るが、窓は 200 万局 × 約 93 手 ＝ 約 1.8 億局面あり、やり直しの原因になった 920 万局面（窓 10 万局）の 16 倍ある。

- 推奨は **0.90・1 手 ＋ 10 局に 1 局は最後まで打つ**（AlphaGo Zero の形。節約 17%、局/日 1.21 倍、誤投了 2.6%）。
- **1 日に学習へ入る局面の数は変わらない**（0.98 倍）。増えるのは 1 日に取れる勝ち負けの数で、価値の学習には効くが方策には効かない。
- **計測の対局では投了しない**（`evaluate.play_match` が 0 に上書きする）。
- 出典と数値: docs/measurements.md・docs/decisions.md の 2026-09-19、docs/method-evidence.md §2.11。効き目は `bin/libra resign` でランを止めずに測り直せる。

## 4. エンジンの推論を fp16 にする（保留。こちらから持ち出さない）

**2026-09-17 のユーザーの決定で保留**。「今回は報告だけでよい。サイトが WebGPU に対応したり、Windows の配布版で GPU 版を利用できるようにする改修を検討するときに再度提案して」。**引き金が来るまでこちらから持ち出さない。**

- 理由: fp16 が効くのは WSL の CUDA 版エンジンだけで、サイト（onnxruntime-web の wasm ＝ CPU）にも Windows の配布版（CPU 版 onnxruntime）にも効かない。学習の 局/日 にも効かない（自己対局はすでに fp16）。
- 引き金: tenbin-shogi-web の WebGPU 対応、または tenbin-shogi-desktop / Windows 版の GPU 実行（CUDA / DirectML）の話が出たとき。
- 再提案のときに使う実測は `libra-engine-speed-2026-09-17.md`（見込み約 2 倍、1.6〜2.2 倍。ONNX のファイルは約半分になるのでサイトの読み込みには効く。どちらも未検証）。
- **複数葉の同時評価は 2026-09-14 に入れ済み**（`DNN_Batch_Size`、既定 64）なので、2026-09-11 の decisions.md が「速度が要るときに入れる」と書いた 2 つのうち残っているのはこれだけ。

## 5. 今は入れないと決めたもの

**先手の得（対称な置き方で +39〜+90 Elo、組ごとに +11〜+197）を v0.3 の項目にすること**（2026-09-21）。v0.2 の玉配置表の検証対局 196,328 局で確定した値だが、**学習の設定を変える話にはならない**（自己対局は 1〜2 手目の玉を一様に置いているので、先手の得は置き方の偏りから出たものではない。ただしこれは「v0.2 が読み 96 回で自分と打ったときの値」で、ゲームそのものの値でも人同士の値でもない）。人同士のハンデの表を作り直す材料なので、そちらで扱う（measurements.md 2026-09-21、tenbin-shogi-web の docs/decisions.md 2026-09-19）。


**自己対局から後手玉四段目を丸ごと除くこと**（2026-09-21）。理由は**「選ぶ」側の評価が壊れるから**。

天秤将棋は片方が両玉を置き、もう片方が先後を選ぶ。相手が置き役のときは、後手玉が四段目の局面を Libra が評価して「先手を持つ」と答えなければならない。そしてその判断は玉配置表ではなく**ネットが出している**: `libra-engine/src/engine.cpp` の `Engine::scale_move` は `pos.ply() > 1` で false を返すので `scale.json` は 1〜2 手目を置くときにしか効かず、選ぶときの `winrate` は探索＝ネットが返す（docs/protocol.md §2。desktop 0.10.0 から GUI が実際にこれを問い合わせる）。人が置き役になるサイトとデスクトップで起きる場面。

2026-09-11 の decisions.md にも「搾取者 lx の玉配置は後手玉四段目を除く 36×27 から一様（`search.prune_gote_rank4`）。**本体 L-S は設計どおり 36×36 一様のまま（選ぶ側が悪い配置も評価できるように）**」とあり、本体で除いていないのは意図したもの。
