# 搾取者 lx の設定表（起動前の条件、2026-09-22）

`config/lx.toml` は **`config/ls.toml` を土台に、搾取者で違えるところだけを変えたもの**。その違いを 1 行ずつ、
出所・理由・確かめる計測つきで並べる（CLAUDE.md 11。本体の同じ表は docs/ls2-settings.md）。
区分は docs/method-evidence.md と同じ（裏取りあり／一部／記録なし）。
**「記録なし」が残る項目は、起動してから最初の凍結相手の周期で値を決める**（決めた日と根拠をこの表に足す）。
ライセンス: CC BY 4.0。

**搾取者は何のために回すのか**（docs/libra-design.md §4.2）: 本体の価値関数には自己対局の分布の外に穴がある
（Wang+ 2023）。天秤将棋は相手が布石の半分を決められるので、その穴へ誘導するのが囲碁より易しい。
ゼロから学習した搾取者に穴を探させ、見つけた布石を本体の学習分布に混ぜて埋める。
**収束の判定は「ゼロから学習した搾取者の対本体勝率が一定以下で頭打ちになること」**なので、
対本体勝率が物差しであり、それを濁す設定は入れない（下の「投了」）。

## 2. 開いている問い（起動してから確かめる）

- **窓の大半が古い凍結相手との対局になる。** 凍結相手は 25,000 step（約 5 時間、lx の局で約 25,000 局）ごとに
  作り直すのに、窓は 50 万局まで広がる。つまり窓の 95% 以上は**今の相手ではない相手**との対局で、
  搾取者の目的（今の本体の穴を突く）から見ると古い。作り直しても窓は空にならない（`refresh_main` は成績と
  布石だけを区切り、リプレイはそのまま。実装を 2026-09-22 に読んで確かめた）。
  **確かめる計測**: 作り直し直後からの 1 時間ごとの区間勝率を 2026-09-14 の記録（67.6% → 75.3% → 80.1% →
  84.8% → 86.8% → 86.9% → 87.9% → 88.2%）と並べる。立ち上がりが目に見えて遅ければ窓を狭める側に寄せる
  （その場合も 10 万局には戻さない。`window_frac` を下げる）。
- **`threads` 4 と `window_games_max` 50 万局はどちらも仮**（上の表の 6・7）。
- **lx の重みはゼロから始める。** 旧系列 `lx-v1`（step 306,175）と `lx/pool/` の重みは、やり直しの原因に
  なった窓 10 万局・`replay_ratio` 4 で学習したものなので引き継がない。2026-09-13 に二飛香の系列を始めた
  ときも lx はゼロからで、そのとき 4.5 時間で本体と互角になっている（docs/decisions.md 2026-09-13）。

## 3. 起動の前に要ること

1. **`[net]` の形を確かめる**（この表の 2）。1.9M という数字は docs に残っているが、**形（`d_model`・層・
   ヘッド・`d_ff`）はどの文書にも残っていない**。`config/lx.toml` に書いた 192 / 4 / 8 / 768 は、
   パラメータ数が 1,927,154 で「1.9M」にいちばん近い形を計算で当てたもの（同じ式で本体は 10,233,090 と
   一致する）。**ヘッド数は 2 / 4 / 8 で約 1,700 しか変わらないので当てられない。**
   正は**ユーザーの手元の `~/libra-run/lx-v1/config.toml`**（2026-09-17 の改名で残っている旧系列の lx）。
   これを読んでから確定する。
2. **`~/libra-run/lx` を片付ける**。2026-09-21 に乱数初期化のまま 14 分動いた run の重み・チャンク・
   `config.toml` が残っている（docs/decisions.md 2026-09-21）。`lx-junk-20260921` へ避ける。
3. **`config/lx.toml` を main に入れるのは②を始める日にする。** リポジトリに設定を置いた時点で
   「設定がどこにも無い run は起動しない」番人（2026-09-21、終了コード 4）が lx に効かなくなる。
4. 手元で `git pull`（`config.py` に `search.prune_gote_rank4` を足したので、無いと起動のたびに
   「今のプログラムが知らない設定」の WARNING が出る）。C++ は変えていないので作り直しは要らない。
