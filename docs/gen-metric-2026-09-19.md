# 一般化の物差し（M1）が「横ばい」に見える理由（2026-09-19）

結論を先に: **丸暗記ではない。物差しのほうが強さを測るものではないだけで、しかも「注意」を出していた判定は
ノイズが信号の 23 倍あって判定として成立していなかった。** 学習は正常で、止める・設定を変える理由は無い。

数値の出所は `progress` ブランチの `progress/ls.json`（2026-09-19 02:46 の書き出し、step 121,804、総局数 1,449,553）。
40 万局以降の gen の計測 56 回（重複を除いたもの）を使った。

## 1. 丸暗記か（窓の中と held-out の差）

M1 が丸暗記を見るのは「窓の中の局面での相関 − held-out の局面での相関」（差が大きいほど、学習に使った局を
覚えているだけ）。40 万局以降を 4 つに区切った平均:

| 総局数 | 計測回数 | held-out | 窓の中 | 差 |
|---|---|---|---|---|
| 41.2 万 〜 67.1 万 | 14 | 0.6531 | 0.6509 | −0.002 |
| 69.2 万 〜 93.7 万 | 14 | 0.6483 | 0.6568 | +0.008 |
| 94.0 万 〜 119.1 万 | 14 | 0.6480 | 0.6595 | +0.011 |
| 120.7 万 〜 144.4 万 | 14 | 0.6614 | 0.6633 | +0.002 |

閾値は 0.1。**実測は最大でも 0.011 で、10 分の 1 以下**。56 回のうち 22 回は held-out のほうが良い（差が負）。
比較のため、2026-09-17 に学習をやり直す原因になった本物の丸暗記は**窓の中 0.94 対 held-out 0.43（差 0.51）**だった
（docs/status-2026-09-17.md §10）。形がまるで違う。**丸暗記は起きていない。**

## 2. では強さと関係があるか

40 万局 → 145 万局で、`libra rating`（記録した対局を全部まとめて 1 本の目盛りにしたもの）は
**+751.6 → +1115.2 で +364 Elo**（docs/measurements.md 2026-09-19）。同じ区間で held-out の相関は
**+0.008 ± 0.005**（最後の 1/4 の平均 − 最初の 1/4 の平均、t = 1.68 で偶然と区別が付かない）。

**強さが 364 Elo 伸びる間、この物差しは動かない。** 上がりもしないし下がりもしない。

## 3. 上がり続けないのは作りからして当然

- 本将棋（布石のあと）の局面の学習目標は、**その対局の結果 z そのもの**（`libra-league/libra_league/replay.py`
  の `t = np.where(fu, lambda_z * z + (1 - lambda_z) * v41, z)`。λ は布石にしか掛からない）。
  相関の上限は「いまの自己対局の結果がどれだけ局面から読めるか」で決まり、**完璧な評価関数でも 1.0 には届かない**
  （結果は当たり外れのある 1 回の実現値なので、真の勝率と結果の相関は σ(真の勝率) / σ(結果) で頭打ちになる）。
- しかも**試験問題が入れ替わる**。held-out は最新の 20,000 局だけを持つ（同 `heldout_games`、
  `self.heldout = held[-self.heldout_games:]`）。自分が強くなるたびに、自分の新しい対局で試験が作り直される。
- つまり**受験者と試験の両方が毎回変わる自己採点**で、世代をまたいで比べられる数ではない。
  強さを測るのは Elo（M2 最強比・M4 固定の参照・`libra rating`）。

## 4. 「注意」を出していた判定は成立していなかった

`libra review` の M1 には判定が 2 つあり、出ていた「注意」は**丸暗記のほうではなく**
「held-out の相関が 200,000 局で上がっていない」のほう（`gen_min_rise`）。これには問題が 2 つある。

1. **出典が無い。** decisions.md 2026-09-17「やり直しの準備 6」に「**出典なし（Claude の案、ユーザーの了承した
   計画の実装）**。確かめる: 煙テストの判定にこれを使い、**人の判断と食い違った点を記録する**」と但し書きがある。
   今回がその食い違いにあたる。
2. **ノイズが信号の 23 倍ある。** 1 回の計測は 4,000 局面（`gen_positions`）で、相関のばらつきは
   実測 **sd 0.013**（相関 0.65・4,000 標本のときの理論値 0.009 とほぼ一致）。判定は 200,000 局離れた
   **2 点の差**を見るので、その差のばらつきは **sd 0.018**。一方で本当の伸びは 145 万局あたりでは
   200,000 局につき **+0.0008 程度**（§2 の傾きから）。

   つまり判定はコイン投げで、実際に **0.6331 で「注意」（9/18 の 120 万局の節目の記録。20 万局で −0.006）
   → 0.6585 → 0.6614 で「続ける」（9/19 02:46、144 万局。20 万局で +0.003）**と裏返っている。
   同じ軌道の上で、同じ学習で、判定だけが変わった。

## 5. 直したこと（2026-09-19）

- **M1 から「上がっていない」の判定を外した**（`gen_min_rise` を廃止）。M1 が見るのは
  **丸暗記（窓の中との差 > 0.1 で「注意」）**と**下がっていないか**だけにした。
  - 下がりの判定 `gen_max_fall = 0.03`（1 回のばらつき sd 0.013 の約 2 倍）。端の 1 点で裏返らないよう、
    窓の前後それぞれ最大 3 点の**中央値**で比べる。
  - 一度 0.6 を超えた run が 0.6 を割ったら「見直し」（`gen_min_corr`。docs/restart-plan.md §3 M1 の線。
    まだ一度も 0.6 に届いていない学習の初めには当てない）。
- **`progress/<run>.json` に held-out の方策の正解率・交差エントロピーと布石の相関も出す**ようにした。
  価値の相関だけだと「横ばい」の読み分けができないため。
- 反映は次の停止 → 起動でよい（このために止めなくてよい）。

## 6. 未確認

- §3 の上限の式（corr ≤ σ(真の勝率) / σ(結果)）は自分の導出で、出典は無い。実測で上限そのものを測っては
  いない（測るには同じ局面から何度も対局を打ち直す必要がある）。
- 「試験問題が入れ替わるせいで比べられない」を実験で分離してはいない。分けるには古いチャンクを固定して
  世代ごとに測る（`libra genprof` が読める）が、古い局面の答えは弱い世代の対局の結果なので、
  それはそれで別の物差しになる。**強さは Elo で測るという結論は変わらない**ので、今回は入れていない。
