- 対象: `libra-v0.2.pt`（PyTorch のチェックポイント）と `libra-v0.2.onnx`（fp32、opset 17）
- 版: **v0.2**（本体 run `ls` の **step 317,975**、2026-09-21 17:22:02 に到達。自己対局の総局数 **3,600,108 局**）

## 1. 何のモデルか

**天秤将棋**（https://tenbinshogi.com/rules/ 、本リポジトリの規定は [rules.md](rules.md)）を指す AI「Libra」の方策・価値ネット。
1 手目から 40 手目までの布石（駒を打って陣を作る段階）と、41 手目以降の本将棋の両方を 1 つのネットで扱う。
USI を拡張したエンジン（`libra` / `libra.exe`、[protocol.md](protocol.md)）から ONNX Runtime で読み、MCGS（Gumbel AlphaZero 系の探索）の評価に使う。

## 2. ネットの形

**v0.1 から変えていない**（`[net]` は run を替えない限り固定）。

| 項目 | 値 |
|---|---|
| 種類 | Transformer エンコーダ（81 マスをトークンにする） |
| `d_model` / 層 / ヘッド / `d_ff` | 320 / 8 / 8 / 1280（dropout 0.0） |
| パラメータ数 | **10,233,090**（約 10.2M） |
| 入力 `sq` | `float32[batch, 81, 32]`（マスごとの特徴） |
| 入力 `glob` | `float32[batch, 32]`（持ち駒・手数・段階などの大域特徴） |
| 出力 `policy` | `float32[batch, 2268]`（指し手・打ち手のロジット） |
| 出力 `wdl` | `float32[batch, 3]`（手番側の 勝ち / 引き分け / 負け のロジット） |
| 出力 `v41` | `float32[batch, 3]`（41 手目局面の見立て。布石の価値の補助ヘッド） |
| ONNX | opset 17（既定ドメイン）、IR 8、バッチ可変、producer `pytorch 2.11.0` |
| ONNX のメタデータ | `libra_step=317975`、`libra_net={"d_model":320,...}`、`libra_source=libra-v0.2.pt`、`license=Apache-2.0` |

特徴量の作り方は `libra-sim`（`Position.features`）と `libra-net/libra_net/` が正。`.pt` には `model`・`opt`・`step`・`rng`・`config`・`state` が入っている（学習の再開用。推論には `model` だけでよい）。

## 3. どう学習したか

**自己対局だけ**で学習した（AlphaZero 型）。教師データ・定跡・人の棋譜は使っていない。

**v0.1 とは別の run で、重みをゼロから学び直している。** 2026-09-17 に、出所を記録せずに決めていた
リプレイの窓（10 万局）と `replay_ratio` 4.0 が「窓の中の対局を覚えるだけ」の状態を起こしていたことが分かり、
学習をやり直した（[decisions.md](decisions.md) 2026-09-17、`docs/restart-plan.md`）。
v0.1 の重み（旧 run の step 477,636）は種にしていない。下の 5.1 の +300 Elo は、やり直した学習が
やり直す前を追い越したうえでどれだけ伸びたかを表す。

| 項目 | 値 |
|---|---|
| 学習の系列 | 2026-09-18 に**ゼロから**始めた run `ls`（2026-09-17 のやり直し。種の重み無し）。ルールは二飛香（[rules.md](rules.md) §3.2） |
| step 317,975 時点 | 自己対局の総局数 **3,600,108 局**、経過 約 82 時間 |
| 自己対局の探索 | 全読み 96 回（確率 0.25）／軽い読み 24 回、Gumbel の候補 16 / 8、`policy_topk` 32、`c_visit` 50.0、`c_scale` 1.0、fp16、同時 512 局・12 スレッド |
| 学習 | batch 1024、lr 2e-4（warmup 1,000）、weight decay 1e-4、**`replay_ratio` 1.0**、**窓 = min(総局数の 50%, 200 万局)**（この時点で 180 万局）、256 局ごとに学習、`grad_clip` 1.0、`mirror_prob` 0.5 |
| 損失の重み | policy 1.0、value 1.0、v41 0.5 |
| 布石の価値目標 | **結果 `z` そのもの（`lambda_z` = 1.0）**。v0.1 の `λ·z + (1−λ)·V̂41`（λ = 0.5）をやめた（[decisions.md](decisions.md) 2026-09-18。200 万局で確認）。§6-1 の偏りはこれで消えた |
| 投了 | **無効**（`resign_threshold = 0.0`）。最後まで指す |
| 搾取者・リーグ | **どちらも使っていない**（`[selfplay] openings = ""`、`[league] enabled = false`）。v0.1 は搾取者の布石を 10% 混ぜていた |
| 玉の置き方 | 1〜2 手目の両玉は**ネットに選ばせず、36 マス × 36 マスから一様乱数**で置く（全 492 組を均等に回すため）。そのため自己対局の 4 局に 1 局は布石だけで終わる（§5.7） |
| 終局規定 | [rules.md](rules.md)（千日手 4 回で引き分け、連続王手は王手側負け、入玉宣言 27 点法、本将棋 320 手、41 手目を 1 手目として数える） |

**クリーンルーム**: 既存の将棋 AI（やねうら王、Apery、dlshogi、Lc0、水匠、Stockfish、fuseki-shogi-ai、fuseki-shogi-web など）のコード・評価関数・重み・棋譜・評価値・読み筋を、内部にも学習信号にも使っていない（[CONTRIBUTING.md](../CONTRIBUTING.md)）。GPL のコードは一行も含まない。

読み方の目安: Elo の差 +100 で勝率約 64%、+200 で約 76%、+300 で約 85%。
区間はすべて 95% で、下限が 0 より上なら「たまたまではない」。

| | 勝 | 敗 | 分 |
|---|---|---|---|
| v0.2 が先手 | 485 | 0 | 0 |
| v0.2 が後手 | 364 | 151 | 0 |

条件は両者とも読み 96 回・根の Gumbel ノイズあり・玉は一様乱数、平均 77.0 手。
引き分けは 0 局。260 局（26%）は 41 手目に進む前に布石の裁定で決着している（§5.7）が、
玉を乱数で置くぶん先後のどちらにも同じだけ起きるので Elo は歪まない。

### 5.7 玉配置表（`scale-v0.2.json`、CC0）と自己対局の分布

v0.2 のネットから作った、天秤将棋の 1〜2 手目に置く両玉の「釣り合う組」の表。
`libra-scale build`（読み 1,600 回、492 組）→ `seq`（全組の検証対局）で作る。
**全 492 組を 196,328 局で打ち切った**（有意 458 組・精度 0.02 まで 34 組。2026-09-21、約 1.4 時間）。
**釣り合う組は 16。** `v_hat_minus_w`（ネットが出す勝率の見込みと実際の勝率の差）は
**−0.0003（標準誤差 0.0026）で 0 と見分けが付かない**（v0.1 は −0.008）。

**対称な置き方では先手が勝つ**（両者の玉が鏡写しなので、残る差は「先に指せること」だけ）:

| 群 | 局数 | 先手勝率 | Elo |
|---|---|---|---|
| 5 筋の同じ高さ 3 組 | 9,477 | 0.5557 | +38.9 |
| 線対称 15 組 | 40,399 | 0.6265 | +89.9 |
| 点対称 15 組 | 42,397 | 0.6007 | +70.9 |

組ごとの差は大きく、▲4八 △6二 の +10.5 から ▲2七 △8三 の +197.4 まで開く。
**これは「v0.2 が読み 96 回で自分と打ったときの値」で、人同士の値ではない。**

自己対局 18,898 局の分布（step 318,234 時点）: 引き分け **0.38%**（千日手 0.08%、連続王手 0.02%、320 手 0.30%）、
平均 **94.2 手**、先手の勝ち **61.3%**。**4 局に 1 局（24.9%）は布石だけで終わる**（41 手目を 1 手も指さないまま、
後手玉が四段目に置かれて先手勝ち）。これは玉を一様乱数で置く設計そのもので、学習の穴でもルールの問題でもない
（[measurements.md](measurements.md) 2026-09-21）。裁定で終わった局を除くと先手は 48.6%。

## 6. 既知の限界

1. ~~布石の価値の見立てが後手寄り~~ **直った。** 布石の価値目標を結果 `z` そのものにした（§3）ので、目標と結果の差 `target_minus_z` は 0.000。§5.7 の `v_hat_minus_w` −0.0003 ± 0.0026 も偏りが無いことを裏づける。**ただし補助ヘッド `V̂41` 自体は結果より 0.046 低いまま**（`v41_minus_z` −0.046）。目標には混ざらないので学習には効かないが、`v41` の出力をそのまま読むときは低めに出ることに注意する。
2. ~~布石の引き分け確率が実態と合わない~~ **直った。** 学習目標の引き分け確率 0.0032 と実際の引き分け 0.0032 が一致している。
3. **搾取者に対する穴は未計測。** v0.1 では 1.9M パラメータの搾取者が 10.2M の本体に 86〜90% 勝っていた。今の系列では搾取者（`lx`）を回していないので、**この穴が残っているかどうかは測っていない**。
4. **本将棋（41 手目以降）の読み抜けは未確認。** 外部エンジンとの対局が無い（§5.6）ので直接は測れていない。自己対局では本将棋の局面で探索値が結果より 0.054 低く出る（`rootq_minus_z_normal` −0.0543）状態が続いている。
5. **強さを揃えた条件で、外部の相手と測っていない。** §5.1〜5.5 はすべて自分の過去の版が相手で、絶対的な強さは分からない。外部エンジンに対する強さは 1.0 で測る。
6. **ルールの版が固定。** 二飛香を含む今の [rules.md](rules.md) だけを扱う。`Fuseki_Rules` を名乗らないので、二飛香より前の棋譜を読ませると `info string bad position` と `bestmove resign` になる。
7. **入力は 天秤将棋 / 布石将棋 専用。** 本将棋（通常の将棋）の初期局面からは指せない。

## 7. 使い方

```
# Linux（ONNX Runtime、CUDA / CPU）
bin/libra-usi                     # DNN_Model に libra-v0.2.onnx を指す

# Windows（配布物の zip）
libra.exe                         # 隣の libra.onnx と scale.json を読む。既定は DirectML
```

USI の申告と `info` の形式は [protocol.md](protocol.md) §3。天秤将棋の GUI（tenbin-shogi-desktop 0.10.0 以降）は
1 回登録すれば 1 手目から終局まで指させられる（同 §1・§2）。
**v0.2 から `Scale_Table` の既定が実行ファイルの隣の `scale.json` になった**ので、zip を展開したまま登録すれば
GUI で何も入れなくても玉配置表が使われる（v0.1 では手でパスを入れる必要があった）。
**v0.1 の `libra.exe` を登録済みの人は、入れ替えたあとに GUI でエンジンを登録し直す**（名乗りが `LibraShogi 0.0.2` から `0.2.0` に変わり、一覧の表示名が変わるため）。

## 9. 配布物の作り方

```bash
# 1. Windows 版をクロスビルド（libra-engine/README.md）
export PATH="$PWD/.venv/bin:$PATH"   # cmake と ninja は pip 版（sudo が使えないため）
cmake -S . -B build-win -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64-posix.cmake \
  -DLIBRA_BUILD_PYTHON=OFF -DLIBRA_BUILD_TESTS=OFF -DLIBRA_ORT_DIR=$PWD/third_party/onnxruntime/onnxruntime-win-x64-directml-1.24.4
cmake --build build-win
# 2. Release に載せるものを作る（zip・SHA256SUMS）
tools/package_release.sh v0.2 ~/libra-run/releases/v0.2 '2026-09-21 17:22:02'   # 末尾は自己対局の標本の中心の時刻
```

zip の中身は `libra.exe`、DirectML 版 ONNX Runtime 1.24.4 と DirectML 1.15.4 の DLL、`libra.onnx`（＝`libra-v0.2.onnx`）、
`scale.json`（＝`scale-v0.2.json`）、`README.txt`、`MODEL-CARD.md`、`LICENSES/`（Apache-2.0・CC BY 4.0・CC0 1.0・NOTICE・
依存物の全文と ThirdPartyNotices）。zip と標本の gzip は日時を固定して詰めるので、同じ入力からは同じ SHA-256 になる。

エンジンが名乗る版は `id name LibraShogi 0.2.0`（`libra-engine/src/engine.cpp` の `VERSION`。エンジンの版で、重みの版とは別。v0.1 は `0.0.2` だった）。
